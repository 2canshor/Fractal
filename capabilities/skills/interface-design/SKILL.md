# Interface Design

Select one mode from the request:

- `direction` when the visual language or hierarchy is undecided;
- `build` when implementing or reshaping an interface;
- `review` when checking an existing interface;
- `reference` when a bounded design fact or pattern must be found.

For direction or build, read [references/direction.md](references/direction.md). For review, read [references/review.md](references/review.md). Load both only when the task genuinely needs both creation and independent review.

Ground decisions in the product, audience, content, existing brand, platform, and quiet constraints. Verify the rendered interface at the surfaces the user will use. Do not treat a database recommendation, screenshot, generated code, or local build as proof of accessibility, deployment, backend behaviour, or cross-device use.
