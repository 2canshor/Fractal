# Learn

Use after Carson has completed a formal Project. If the canonical Project is not primary-user-completed, stop and show that exact requirement; this Command cannot declare Project Completion.

Complete the System Review before Carson sees any decision. Follow the eight Blueprint Flows in order: Observe; Group; Connect; Explain; Explore; Map; Challenge; and Decide. These are concise display names for the existing stable Flow ids and use rules, not new Elements. Curiosity supports solution search, Blueprint Mapping must finish before Challenge, and Two-Sided Review supports every consequential challenge. A genuine zero-pattern Project may end in No Change without inventing an observation. Finish each ordinary-language handoff as: the problem, the proposed solution, and Carson's decision.

If a required mechanism can run within existing authority, finish it without making Carson wait at the desk. If it cannot run, return `review_incomplete` with the exact missing mechanism. Preserve a true Project Completion even when review preparation is incomplete.

Review readiness does not approve any result, implement a change, build or activate a System Version, or publish to GitHub.
