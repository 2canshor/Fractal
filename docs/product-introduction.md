# Fractal in One Competition Project

Imagine a student opens Fractal and says: “I want to enter a technology competition with an app that helps people notice hidden emotion in messages.”

## 1. Form the Project

Fractal records that sentence as the **Brief**. The agent turns it into a provisional **Project Direction**: understand the problem, build a working app, and prepare competition evidence.

The agent researches the competition rules, intended users, existing approaches, and technical limits. When a choice changes the outcome, it asks a short **Clarification**. For example: “Should the first version help friends and classmates, or trained counsellors?” The student's answer changes the product direction, so Fractal records it.

The student then approves:

- **Goal:** submit a working, evidence-backed app that helps students recognise emotional subtext;
- **Success Criteria:** the core flow works, real testing supports the claim, the pitch matches the product, and the submission files meet the rules;
- **Priorities:** user value first, reliable evidence second, presentation polish third;
- **Project Plan:** research, prototype, user test, build, verify, and prepare the submission.

## 2. Reach a Milestone

After research and the first prototype, Fractal opens a **milestone Project Review**. The prototype is the trigger, but the review checks the whole Project.

It finds that the Goal still fits, the Success Criteria remain useful, and the evidence is promising. It also finds that the Plan placed visual polish before user testing. The review updates the Plan so user testing happens first and preserves both Plan versions.

## 3. Handle an Exception

During responsive testing, the same layout repair is attempted three times. The Work Signatures let Fatigue recognise the repetition. Curiosity researches a smaller test method. These findings enter an **exception Project Review**.

That review checks the full Project again. The Goal and Success Criteria stay unchanged. The main risk is now the deadline. The Plan changes from “keep repairing each screen” to “fix the shared layout rule, run four representative screen tests, then continue the submission.” The review records the evidence and the biggest remaining concern: one screen size still lacks a real-device check.

## 4. Complete the Project

When every approved Success Criterion has evidence, Fractal shows the Project as ready for completion. The student reviews the result and explicitly declares **Project Completion**.

## 5. Review Fractal Afterward

System Review now studies how Fractal should work better on future Projects:

1. **Project Assessment:** records what went well and what could be better.
2. **Issue Scan:** gathers many possible issues before narrowing them.
3. **Project Patterns:** finds repeated behaviour inside this Project.
4. **Cross-Project Patterns:** states that history is insufficient if this is the first comparable competition Project.
5. **Reversal Check:** checks whether Fractal previously added and removed similar rules.
6. **Cause Research:** when needed, External Research and Internal Review investigate separately; Reconciliation combines their evidence.
7. **Improvement Options:** considers deleting, shortening, merging, simplifying, modifying, adding, and keeping the current system.
8. **Expected Effect:** states what each serious option is expected to improve.
9. **Local Effect and Global Effect:** checks the effect on competition work and on every other kind of Project.
10. **Two-Sided Review:** for a consequential change, independent Case For and Case Against branches make their strongest arguments.
11. **Final Assessment:** the Main Agent weighs all evidence.
12. **Biggest Remaining Concern:** names the main unresolved risk plainly.
13. **Result:** produces a Change Proposal, Experiment, Need More Evidence, or No Change.
14. **Your Decision:** the student accepts the result, rejects it, or gives feedback.

If the student gives feedback, Fractal records reasons supporting it, reasons challenging it, an updated Final Assessment, and an updated Biggest Remaining Concern. The student decides again.

That is Fractal's continuous-improvement loop: protect the current Project while it is happening, then learn from the completed Project for the next one.
