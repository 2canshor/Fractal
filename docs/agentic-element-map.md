# Agentic Element Map

The [Blueprint](blueprint.md) defines meaning. This map explains implementation responsibility without creating another architecture.

| Blueprint element | Role | Primary executor | Supporting executors |
|---|---|---|---|
| System Review | # Protagonist | Main Agent | deterministic runtime, Skills, evidence Methods |
| Steps 1–8 | $ Deuteragonists | Main Agent | deterministic stage validator and supporting Methods |
| Fatigue | $ Value | deterministic program | Work Signature, Main Agent |
| Curiosity | $ Value | Skill and Main Agent | research Tools |
| Greed | $ Value | Skill and Main Agent | comparison and trial machinery |
| Perspective | $ Method | Main Agent | lifecycle runtime, Hooks, verifier |
| Principles | % | deterministic and reasoning checks | all relevant implementations |
| Infrastructure | ^ | deterministic programs, Hooks, adapters | operator views |
| Cause Research | ¢ Method | independent reasoning branches | research Tools |
| Two-Sided Review | ¢ Method | independent opposing branches | Main Agent synthesis |
| Steal | ¢ Method | governed donor intake | Blueprint Mapping and Component Governance |

The System Review runtime preserves smaller internal records for evidence, effects, debate, and decisions. Every record names the canonical Blueprint Step it supports. Reality Check effect records are marked supporting Infrastructure rather than being presented as a Step.

Technical identifiers may retain compatibility names such as `project-review`. Human-facing names and generated descriptions use Perspective.
