## Section 2 — Flows

Flows are ordered use rules owned by `System Review`; they are not Genres or Elements.

### 1. Find Problems

- Starts when: System Review starts from completed Project evidence or a verified improvement opportunity.
- Uses: `Work Signature`, `Hooks`, `Reality Check`, `Fatigue`, `Greed`, `Quantity over Quality`
- Produces: A broad, provenance-linked observation set without premature causes.

### 2. Find Local Patterns

- Starts when: Flow 1 has persisted a valid observation set.
- Uses: `Work Signature`, `Fatigue`, `Cause Research`, `Quantity over Quality`
- Produces: Local recurrence groups with surface similarity kept separate from cause.

### 3. Find Global Patterns

- Starts when: Flow 2 has persisted local patterns and comparison scope.
- Uses: `Perspective`, `Cause Research`, `Global Outcome over Local Optimisation`, `Component Governance`
- Produces: Whole-Project pattern candidates linked to local evidence and relevant history.

### 4. Find the Reasons for Every Global Pattern

- Starts when: Flow 3 has persisted every Global Pattern candidate.
- Uses: `Cause Research`, `Curiosity`, `Reality Check`, `Two-Sided Review`
- Produces: A bounded causal account for every Global Pattern, including uncertainty and counterevidence.

### 5. Find Solutions for Every Global Pattern

- Starts when: Flow 4 has persisted a causal account for every Global Pattern.
- Uses: `Curiosity`, `Greed`, `Steal`, `Experiment`, `Reality Check`, `Subtraction First`, `Global Outcome over Local Optimisation`
- Produces: Multiple evidence-backed Solution Candidates per Global Pattern, including a truthful no-finding result.

### 6. Map New Implementations into the Blueprint

- Starts when: Flow 5 has persisted its complete Candidate set.
- Uses: `Steal`, `Component Governance`, `Donor Quarantine`, `Donor Registry`, `Environment Adapters`, `Naming System`, `Capability Check`, `Human Control`, `Deterministic over Probabilistic`, `Subtraction First`
- Produces: Every Candidate is classified against the Element Library and Section 3 rules before debate.

### 7. Debate the Solutions for Every Global Pattern

- Starts when: Flow 6 has mapped or honestly rejected every Candidate.
- Uses: `Two-Sided Review`, `Experiment`, `Reality Check`, `Global Outcome over Local Optimisation`, `Human Control`, `Deterministic over Probabilistic`
- Produces: Independent opposing cases and a reconciled recommendation for every decision unit.

### 8. Present Decisions One-by-One

- Starts when: Flow 7 has completed both opposing cases and reconciliation.
- Uses: `Human Control`, `Perspective`, `Reality Check`, `Component Governance`
- Produces: One prepared human decision at a time, with the remaining queue visible and no automatic activation.

## Tags

- `Signature Function` is a cross-Genre Tag, not a Genre.
- Current members: `Fatigue`, `Curiosity`, `Greed`, and `Perspective`.

## Section 3 — Blueprint Change Rules

- There is one Protagonist: `System Review`.
- Every persistent Element Library member belongs to exactly one Genre.
- A Flow is neither a Genre nor an Element.
- Every Flow may use only capabilities registered in the Element Library.
- A Deuteragonist preserves its core concept while its implementation may change.
- An Extra stays outside product emphasis and supports an existing `#` or `$`.
- A Prop is a reusable Method and never owns a lifecycle or authority boundary.
- A Principle is asymptotic and cannot be claimed complete.
- Addition priority is `^ → ¢ → % → $`; classification must remain truthful.
- Every Candidate implementation is mapped into the Blueprint before debate.
- The New Blueprint supersedes conflicting architecture claims in the old plan.

## Donor Boundary

- Hermes is governed as the first researched donor, not a permanent donor choice.
- Donors are selected separately for the current Element need.
- Reused implementation is forked locally and cannot require the donor service to stay online.
- Fractal uses its own capability names instead of donor product names.
- Donor implementations may be reused; donor architecture and mutation authority may not.
- Unclassified donor capabilities remain quarantined.
- Bulk donor import is prohibited.

## Steal and Curiosity

- `Curiosity` decides when implementation evidence beyond the current method is needed.
- `Steal` is that Value's bounded donor-facing acquisition and adaptation route.
- `Steal` serves Flow 5, hands every Candidate to Flow 6, and cannot replace `Perspective`, `Cause Research`, or `Two-Sided Review`.
